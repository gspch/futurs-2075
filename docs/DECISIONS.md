# Journal des décisions

Chaque choix ambigu est tranché ici, avec sa raison. Ordre chronologique.

| # | Décision | Raison |
|---|----------|--------|
| D1 | Le jeu s'appelle **Aiguillages**. | Un aiguillage se franchit une fois : l'image porte à la fois la dépendance au chemin et l'irréversibilité, sans jargon de prospective. Nom français, court, sans équivalent connu dans le jeu de société. |
| D2 | Un seul monde partagé par tous les joueurs, pas un tableau par joueur. | On ne construit pas chacun son futur : on se dispute le même. C'est ce qui rend l'interaction réelle et donne un sens à l'écart entre futur probable (où va le monde) et futur souhaitable (où je voudrais qu'il aille). |
| D3 | Curseur d'interaction : **compétitif à alliances de circonstance** (un seul gagnant, visions secrètes qui se recoupent partiellement). | Deux joueurs qui veulent le même pôle coopèrent de fait sur cet axe tout en s'opposant ailleurs. Pas de coopératif pur (le sujet deviendrait moralisateur : « le bon futur »), pas de compétitif pur (le monde commun n'aurait pas de sens). |
| D4 | Quatre axes bipolaires dont aucun pôle n'est « le bon » : Matière (Sobriété/Abondance), Technique (Outil/Automate), Échelle (Local/Global), Lien (Autonomie/Commun). | Neutralité : chaque pôle est défendu par des courants réels du débat prospectif. Le contenu est strictement symétrique (7 tendances, 2 ruptures, 2 visions principales par pôle). |
| D5 | Code et identifiants en français (`jouer`, `coupsLegaux`, `Etat`). | Le vocabulaire du code est celui des règles : un contributeur lit la règle et retrouve la fonction. |
| D6 | Dépôt : un seul `package.json`, dossiers `moteur/`, `bots/`, `simulateur/`, `web/`, `contenu/`, `outils/`, `docs/`. Imports relatifs, pas d'espaces de travail npm. | « Monorepo simple » : moins d'outillage, même séparation des responsabilités. |
| D7 | Branche de travail `claude/sweet-dijkstra-alv48d`, devenue branche par défaut du dépôt (première branche poussée dans un dépôt vide). Les workflows se déclenchent aussi sur `main`. | La session n'est autorisée à pousser que sur cette branche. La renommer en `main` est une action d'un clic pour le propriétaire ; rien d'autre n'est à changer. |
| D8 | L'expert est une recherche Monte-Carlo à la racine (UCB1) sur mondes déterminisés, avec déroulements tronqués après le prochain bilan puis évaluation heuristique, plutôt qu'un arbre MCTS complet. | « MCTS ou équivalent » : avec de l'information cachée et du hasard, un arbre profond sur un seul monde tiré triche ou se disperse. Le bandit à la racine sur plusieurs mondes est l'équivalent honnête et rapide (≈ 40 ms par décision). |
| D9 | Tous les bots non experts partagent une même fonction d'évaluation et ne diffèrent que par leurs poids (`bots/src/bots.ts`). | Les stratégies sont « toutes paramétrables » comme demandé, et le test adverse peut explorer l'espace des poids. Les bots ne reçoivent qu'une observation masquée de l'état. |
| D10 | Critère 4 (retour du dernier) mesuré à la fin de la 3ᵉ décennie (2055, soit 60 % de la partie), sur les tables sans bot aléatoire. | 2055 est plus exigeant que 2045. Un bot qui joue au hasard est presque toujours dernier et ne revient jamais : l'inclure mesurerait sa faiblesse, pas la possibilité de retour. Les deux mesures (2045 et 2055) figurent dans le rapport. |
| D11 | Critère 5 : la « présence » d'une carte est rattachée au joueur qui l'a jouée (tendance installée, signal parié, rupture préparée, vision détenue) et comparée à sa part attendue 1/n. | Dans un monde partagé, une carte « présente dans la partie » l'est pour tous : seule l'association carte-joueur peut déplacer un taux de victoire. |
| D12 | Les tags de version et la release GitHub ne sont **pas** créés sur le dépôt distant. | La session ne peut pousser que la branche `claude/sweet-dijkstra-alv48d` (le proxy git refuse les tags, HTTP 403). J'ai envisagé de les faire créer par un workflow GitHub Actions ; cette voie a été refusée par le garde-fou de la session comme contournement d'une restriction voulue, et je m'y suis tenu. Les versions sont décrites dans `ITERATIONS.md` avec leur commit, les notes de version sont prêtes dans `docs/NOTES_DE_VERSION_v1.0.md`, et les PDF à attacher sont dans `docs/`. Commande pour le propriétaire : voir ce fichier de notes. |
| D13 | Le déploiement GitHub Pages n'est tenté que depuis `main`. | L'environnement `github-pages` du dépôt refuse les déploiements depuis la branche de travail (règle de protection). Le workflow construit et teste le site à chaque push, et déploie dès que la branche s'appelle `main`. Pousser sur `main` m'était interdit. |
| D14 | Visions à **case cible** plutôt qu'à direction (v0.4). | Voir `ITERATIONS.md` : c'est le changement qui a rendu le jeu profond. Deux visions principales par pôle, une réformiste (2 cases du centre) et une radicale (4 cases). |
| D15 | « Mi-partie » pour le critère 4 : 2055, mesure omnisciente (score que chacun aurait si la partie s'arrêtait là), et non le score public. | Avec des visions secrètes, le « dernier » perçu à table (points d'anticipation) n'est pas le vrai dernier. La mesure omnisciente est la plus sévère ; c'est elle qui est retenue. La mesure à 2045 est donnée à côté. |
| D16 | Conversion durée simulée → minutes : 6 min de mise en place, 38 s par décision et 2 min 30 par bilan à table ; en ligne 40 s par décision humaine, 2,5 s par décision de bot, 1 min 12 par bilan. | Hypothèses de l'auteur, non mesurées sur des humains ; elles sont exposées dans le rapport et listées dans les questions à vérifier en partie test. Elles n'ont pas été ajustées pour faire passer le critère 7. |
| D17 | Trois niveaux de bots en ligne : facile = glouton très bruité qui joue au hasard une fois sur quatre ; moyen = glouton, chasseur, bloqueur ou parieur selon le siège ; difficile = expert (260 déroulements par décision). | « Trois niveaux issus de ces stratégies » ; la variété des adversaires moyens montre plusieurs façons de jouer. |
| D18 | Le plateau est un PDF séparé (`docs/PLATEAU.pdf`, A4 paysage) ; les jetons sont la dernière page de `CARTES.pdf`. | Un seul PDF ne peut pas mêler proprement portrait et paysage avec l'outil retenu. |
